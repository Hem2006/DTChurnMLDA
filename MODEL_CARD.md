# Model card: Evergreen churn model

All figures below are read from `churn_model_meta.json` (regenerated by `train.py`, seed 42). Where they differ from the
figures in the original brief, the brief's figure came from the original artifacts, which no longer load (see Provenance).

## Intended use
Rank current telecom customers by churn risk so a retention offer can be targeted, and show per-customer reasons for flagged customers.
Not for: pricing decisions, credit/eligibility decisions, or any use that treats a score as a cause. The digital twin / what-if
simulator is a **model-sensitivity tool, not a causal estimate**. Contract effects in particular reflect selection (loyal customers
choose long contracts) and will overstate any real-world effect. Any uplift model built on this data is trained on **simulated**
treatment (the data has no treatment column).

## Data
IBM/Kaggle Telco Customer Churn (7,043 customers, churn rate 26.5%). 80/20 stratified split, seed 42: 5,634 train / 1,409 test.
17 inputs: SeniorCitizen, Partner, Dependents, tenure, PhoneService, MultipleLines, InternetService, OnlineSecurity, OnlineBackup,
DeviceProtection, TechSupport, StreamingTV, StreamingMovies, Contract, PaperlessBilling, PaymentMethod, MonthlyCharges.
`gender` and `TotalCharges` are dropped (ablation: no AUC benefit; TotalCharges is ~tenure x MonthlyCharges). `gender` is still audited.

## Model
XGBoost (tuned by randomized search, selected by nested CV, ties broken toward XGBoost) wrapped in `CalibratedClassifierCV`
(isotonic, 5-fold ensemble, method chosen by out-of-fold Brier on train only). Served probabilities are the calibrated ones.
SHAP explanations average the 5 fitted base pipelines of the served ensemble (log-odds of the base XGBoost score; isotonic is a monotone
map on top). Averaged top-3 reasons agree with the old single-pipeline explainer's top-3 on 94.8% of picks (300 test rows; every
row shares at least 2 of 3).

## Baseline and model-family comparison
Nested CV AUC (5 outer folds, train set): Contract + tenure baseline 0.785; logistic regression 0.8437 (sd 0.018);
random forest 0.8462; **XGBoost 0.8500** (sd 0.017); LightGBM 0.8502. Test AUC of the Contract + tenure baseline: 0.798, so the 17-input
model adds about 0.05 AUC over the simple baseline.
**Logistic regression is within noise of XGBoost**: the 0.0064 nested-AUC gap is about a third of one outer-fold standard deviation.
The tree model is kept for the calibrated-ensemble and SHAP tooling, not because it is demonstrably better. A plain logistic-regression
reference (`churn_logreg_ref.joblib`, test AUC 0.838, class-weight balanced so its probabilities are not calibrated) is kept to sanity-check the twin.

## Threshold (placeholder)
`config.yaml` has no offer cost, customer value or success rate, so the threshold is the **labelled placeholder** 0.315
(F1-optimal on calibrated out-of-fold scores; F1 treats a missed churner and a wasted offer as equally costly, which is unlikely to be
true). Every API response says `threshold_source` and `threshold_is_placeholder`. With real numbers the threshold becomes
offer_cost / (success_rate x customer_value); for illustration only, 20 / 800 / 0.30 would give 0.083.

## Subgroup behaviour (test set, at the placeholder threshold)
| Group | n | churn rate | flag rate | recall | precision |
|---|---|---|---|---|---|
| Female / Male | 687 / 722 | 0.28 / 0.25 | 0.37 / 0.37 | 0.74 / 0.78 | 0.55 / 0.53 |
| SeniorCitizen 0 / 1 | 1187 / 222 | 0.23 / 0.44 | 0.32 / **0.63** | 0.71 / 0.88 | 0.51 / 0.62 |
| Partner No / Yes | 736 / 673 | 0.34 / 0.19 | 0.49 / 0.24 | 0.82 / 0.64 | 0.56 / 0.49 |
| Dependents No / Yes | 978 / 431 | 0.31 / 0.17 | 0.46 / 0.18 | **0.81 / 0.55** | 0.55 / 0.51 |

The model misses far more churners among customers with dependents (recall 0.55 vs 0.81) and flags seniors at 63% (their true churn
rate is 44%). Flag-rate gaps partly reflect real churn-rate differences; the recall gap is the one to investigate. Groups are small
(222 seniors), so these gaps are noisy. No fairness mitigation has been applied.

## Known limitations
- Old public dataset from a single (fictional) telco; no evidence it matches current customers. Retrain and re-validate on own data.
- Small test set (1,409 rows): AUC CI spans about +/-0.02, so differences between model families below that are not detectable.
- Churn is correlated, not caused, by the inputs. Offers have never been randomised here, so no effect of any action is measured.
- Calibration is checked on one test split; recalibrate if the population shifts.
- Hyperparameters were tuned on the same training rows used for the repeated-CV figure (mildly optimistic); the nested figures are the fair ones.

## Provenance
`train.py` rebuilds everything from the CSV. A retrain reproduced the originally saved test AUC (0.8472) to within 0.0009 (0.8481).
It did not reproduce them exactly: threshold 0.315 vs 0.340, recall 0.757 vs 0.730, Dependents=Yes recall 0.55 vs 0.52, senior flag rate
63% vs 59%, nested XGBoost AUC 0.8500 vs 0.8496. The original `churn_model.joblib` / `churn_xgb_explainer.joblib` could not be loaded under
the pinned XGBoost 3.4.1 ("input stream corrupted") and are kept unmodified in `legacy_artifacts/`.
